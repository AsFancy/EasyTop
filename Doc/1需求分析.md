## 1. 项目概述

### 1.1 产品定位

EasyTop 是一款 Windows 桌面常驻型个人助手。它以“桌面层挂件”的形态与壁纸融为一体，平时不遮挡、不打扰任何应用；通过全局快捷键可临时置顶唤出，集中完成快捷启动、日程规划与任务管理。

### 1.2 目标用户

- 希望桌面保持整洁、常用程序一键可达的 Windows 用户。
- 需要轻量日程/待办管理，但不想打开大型日历或项目管理工具的用户。
- 注重隐私、偏好数据本地保存的用户。

### 1.3 核心价值

- **一眼掌握**：今日日期、农历、节假日、临期任务与常用程序集中在同一面板。
- **不打扰**：常驻桌面层，不覆盖应用、不抢焦点、不占任务栏、不弹系统通知。
- **随时唤出**：一个全局快捷键临时置顶，用完即收。
- **数据自持**：数据只存在本地固定文件夹，整体替换即可迁移。

### 1.4 设计原则

- 桌面优先，非必要不打扰。
- 手动状态由用户掌控，只有到期判定交给系统。
- 本地优先，离线可用。
- 不修改系统设置、不注入其他进程、不接管桌面图标。

## 2. 名词定义

| 名词 | 含义 |
| --- | --- |
| 桌面层 | 壁纸与普通应用窗口之间的层级；该层窗口会被所有普通窗口覆盖，Win+D 后仍可见。 |
| 桌面模式 | 挂件位于桌面层、被动显示的默认状态。 |
| 置顶模式 | 通过全局快捷键把挂件临时提升到最顶层、可交互的状态。 |
| 被动出现 | 启动、刷新、状态更新等非用户点击触发的显示行为。 |
| 不抢焦点 | 仅指被动出现时不夺取当前应用焦点；用户主动点击挂件则正常激活，当前应用转为非激活但不最小化。 |
| 钉住模式 | 面板主体鼠标穿透、仅作展示不可操作的状态；顶部控制栏保留可点，用于解除。 |
| 锁定状态 | 面板内容整体遮蔽、需密码才能恢复查看与操作的状态。 |
| 全天任务 | 只有日期、没有具体时段的待办。 |
| 定时任务 | 同一天内带有开始/结束时间的待办（本期不跨天）。 |
| 手动状态 | 用户自行设定的任务状态：未开始 / 进行中 / 已完成。 |
| 系统状态 | 按时间自动判定的任务状态：即将到期 / 已延期。命中时覆盖手动状态的显示。 |
| 即将到期 | 未完成且截止时间落在“临期阈值”内的任务。 |
| 已延期 | 截止时间已过且未完成的任务。 |
| 临期区 | 主页今日信息卡内固定展示即将到期与已延期任务的区域。 |
| 快捷方式项 | 启动台内的条目，统一以快捷方式文件指向目标，不移动目标本身。 |
| 法定节假日数据 | 含放假日期、调休上班日、节日名称的年度数据。 |

## 3. 边界与硬约束

### 3.1 形态约束

```
壁纸
 └─ 桌面层：系统桌面图标 / EasyTop 挂件 / 其他桌面挂件
     └─ 普通应用窗口
         └─ 置顶窗口 / 全屏应用
```

- FR-3.1.1 挂件位于桌面层，采用固定形态显示，不接管、不隐藏、不移动系统桌面图标。
- FR-3.1.2 普通窗口打开或最大化后完全覆盖挂件，属预期行为；桌面模式下的可见性依赖 Win+D 或全局快捷键。
- FR-3.1.3 挂件不显示在任务栏和 Alt+Tab 列表中。
- FR-3.1.4 被动行为不得抢占焦点：启动、页面刷新、壁纸变化重绘、任务进入临期状态时，当前应用保持激活状态。
- FR-3.1.5 主动点击挂件时允许其获取焦点：当前应用转为非激活（不最小化、不改变窗口状态），与点击桌面空白处表现一致。此取舍以保证输入法、Esc 与键盘操作可用。
- FR-3.1.6 严禁通过窗口钩子、鼠标捕获、Shell 替换等方式影响其他软件的正常启动与使用。
- FR-3.1.7 面板尺寸可由用户调整，必须设置最小/最大限制。
- FR-3.1.8 只管理自身面板与数据，不为任何其他窗口提供置顶、透明或穿透能力。

### 3.2 运行约束

- FR-3.2.1 严格单实例运行；重复启动时唤醒已有实例。
- FR-3.2.2 隐藏状态与退出状态下的临期任务仅在下次打开时重新计算，不产生任何外部提示。
- FR-3.2.3 前台为全屏应用（游戏、视频、演示）时自动隐藏挂件，退出全屏后恢复；该行为可关闭。
- FR-3.2.4 同一时间只显示一份挂件；可选择显示在哪个显示器，默认主显示器；显示器增减、分辨率或 DPI 变化后自动校正位置。
- FR-3.2.5 全局快捷键必须可自定义；注册失败时提示冲突并引导修改。

### 3.3 安全约束（锁定）

- FR-3.3.1 支持手动锁定；系统锁屏 / 休眠时可自动锁定（可在设置中关闭自动锁定）。
- FR-3.3.2 锁定后不可查看、不可操作任何页面内容；不允许通过托盘菜单、全局快捷键或进程重启绕过。
- FR-3.3.3 解锁需输入密码；连续输错 5 次后锁定 30 秒，超时后逐次递增等待时间。
- FR-3.3.4 密码在首次启用锁定时设置，之后可修改；修改需先输入当前密码。
- FR-3.3.5 密码不得明文保存，必须使用加盐哈希。
- FR-3.3.6 忘记密码时唯一恢复方式为重置：清空全部本地数据（任务、启动项、设置、密码），恢复首次启动状态；重置需二次确认并明确不可撤销。
- FR-3.3.7 锁定状态跨重启保持，启动后仍为锁定。
- FR-3.3.8 锁定期间系统状态照常按时间推导，但界面不展示，解锁后按当前时间重新计算并展示。
- FR-3.3.9 自动锁定仅在已设置密码时生效；未设置密码时点击“锁定”应先引导设置密码。

### 3.4 功能范围

- FR-3.4.1 提供四类功能：主页（今日信息 + 快捷启动台）、日历、任务、设置。
- FR-3.4.2 主页内容固定，不提供修改入口。

## 4. 功能需求

### 4.1 快捷启动台

- FR-4.1.1 支持收纳：程序（`.exe` / `.lnk`）、文件、文件夹、网址。
- FR-4.1.2 支持从资源管理器或桌面拖入；网址通过“新建网址”对话框添加。
- FR-4.1.3 拖入程序、文件、文件夹时，在数据目录内自动生成对应的 `.lnk` 快捷方式指向原目标；拖入网址时生成 `.url`。原目标位置不变、不复制、不移动。
- FR-4.1.4 拖入的本身就是快捷方式时，解析其目标后重新生成，避免多级套用。
- FR-4.1.5 自动读取显示名称与图标；名称可修改。
- FR-4.1.6 网址默认用域名首字母生成图标，不在后台联网抓取 favicon（与“默认不联网”原则一致）。
- FR-4.1.7 快捷方式指向的目标不存在时标记“失效”，并提供重新定位或移除入口。
- FR-4.1.8 单击或双击启动可配置，默认双击；启动失败给出明确提示。
- FR-4.1.9 支持按名称搜索过滤。
- FR-4.1.10 支持分组，条目可在分组间移动。
- FR-4.1.11 不扫描、不隐藏、不移动系统桌面图标；不修改文件关联与默认程序。
- FR-4.1.12 快捷方式文件随数据文件夹一起迁移，替换数据文件夹后启动台内容随之更新。

### 4.2 今日信息

- FR-4.2.1 显示公历日期、星期、农历日期；农历可含干支与生肖。
- FR-4.2.2 显示当日节气与传统节日（如有）。
- FR-4.2.3 显示最近周末信息：距离周末天数、周末日期、调休上班日提示。
- FR-4.2.4 显示下一个法定节假日名称、开始日期与倒计时；今日为节假日或调休上班日时明确标识。
- FR-4.2.5 显示待办摘要：今日待办数、临期数、已延期数。
- FR-4.2.6 节假日数据未覆盖当前年份时显式提示，不得静默显示错误信息。
- FR-4.2.7 主页必须固定展示所有即将到期与已延期任务（临期区）；无相关内容时展示空状态，不得隐藏该区域。

### 4.3 日历与任务

- FR-4.3.1 日历提供月视图与周视图，均支持上一周期、下一周期与回到当前。
- FR-4.3.2 月视图每格显示公历日、农历日、今日高亮、周末 / 节假日 / 调休标识、当日任务摘要。
- FR-4.3.3 任务字段：标题（必填）、日期、可选开始/结束时间、手动状态、优先级、类别（可选自定义文本）、备注。
- FR-4.3.4 手动状态由用户选择，默认未开始；系统状态按 5.1 判定并覆盖显示。
- FR-4.3.5 定时任务的结束时间必须晚于开始时间，本期不支持跨天。
- FR-4.3.6 支持快速新建：只填标题与优先级，其余取默认值。
- FR-4.3.7 支持在日历中改期，改期不改变时间字段。
- FR-4.3.8 保存成功后日历、任务页与临期区同步刷新，不出现需要手动刷新的情况。
- FR-4.3.9 校验失败时明确提示，不丢失已填内容。
- FR-4.3.10 任务页汇总所有任务；已完成任务默认收起，可按需查看。
- FR-4.3.11 提供按自定义类别分区与按状态分区两种显示模式，并记忆上次选择。
- FR-4.3.12 支持筛选：状态、优先级、日期范围、类别、关键词；关键词搜索范围包含标题、备注与类别。
- FR-4.3.13 支持直接修改手动状态与标记完成 / 取消完成；完成后记录完成时间。
- FR-4.3.14 支持编辑、改期、删除（删除需确认）。
- FR-4.3.15 列表为空时给出引导文案与新建入口。
- FR-4.3.16 周起始日支持周一或周日，默认周一。
- FR-4.3.17 已完成任务的保留策略：待确认（建议永久保留，可筛选查看）。

### 4.4 临期与逾期提示

- FR-4.4.1 不发送 Windows 系统通知、不弹窗、不发声。
- FR-4.4.2 提示的唯一载体是主页今日信息卡内的临期区。
- FR-4.4.3 任务进入“即将到期”或“已延期”时，仅更新其状态；处于置顶或隐藏状态的挂件不主动弹出或闪烁。
- FR-4.4.4 临期区的排序、计数与任务页筛选口径一致（见 5.2）。
- FR-4.4.5 面板处于锁定状态时，临期区随面板一起遮蔽，不提供任何外部提示。

### 4.5 设置

- FR-4.5.1 外观：不透明度、模糊开关与强度、主题、面板尺寸与位置。
- FR-4.5.2 行为：全局快捷键、全屏自动隐藏、单击/双击启动、显示器选择。
- FR-4.5.3 启动：开机自启（可选）。
- FR-4.5.4 日历：周起始日、是否显示农历/节气、临期阈值（默认 72 小时）。
- FR-4.5.5 安全：设置 / 修改锁定密码、系统锁屏时自动锁定开关、清除密码、重置数据。
- FR-4.5.6 数据：打开数据目录、清空数据（二次确认）。
- FR-4.5.7 关于：版本号、许可信息；检查更新是否实现待确认。
- FR-4.5.8 设置项即时生效，无法即时生效的必须明确提示需要重启。

### 4.6 数据管理

- FR-4.6.1 所有数据保存在固定的数据文件夹内，默认不联网、不采集使用数据。
- FR-4.6.2 任务、启动台索引、设置与安全数据以明文形式保存，用户可直接打开查看与手动修改。
- FR-4.6.3 快捷方式项保持系统标准的 `.lnk` / `.url` 文件，随数据文件夹一同保存。
- FR-4.6.4 数据文件夹整体可移植：直接替换该文件夹即可完成数据迁移或更新，无需导入导出操作。
- FR-4.6.5 启动时校验数据文件完整性与版本；文件损坏或版本不兼容时给出明确说明，不得静默清空数据。
- FR-4.6.6 不提供备份、导入、导出、回收站等数据维护功能；迁移由用户手动复制文件夹完成。
- FR-4.6.7 用户手动编辑数据文件导致格式非法时，程序应拒绝加载该部分数据并给出提示，不得崩溃或静默覆盖。
- FR-4.6.8 锁定密码的哈希保存在同一数据文件夹内，替换文件夹会一并替换密码。
- FR-4.6.9 清空数据为不可撤销操作，需二次确认，并同时清除密码。

### 4.7 系统集成

- FR-4.7.1 提供托盘入口，可打开各页面、切换显示/隐藏并退出。
- FR-4.7.2 托盘“退出”与顶部“关闭”行为一致：直接退出；仅在存在未保存编辑时确认，退出后无残留进程。
- FR-4.7.3 开机自启可开关，且能在 Windows 的启动项设置中看到，不写入隐藏位置。
- FR-4.7.4 响应系统主题切换、显示器变化、DPI 变化等事件。
- FR-4.7.5 监听系统锁屏 / 解锁事件：锁屏时按设置自动进入锁定状态。

## 5. 业务规则

### 5.1 任务状态判定

状态由两部分组成：

- **手动状态**：未开始 / 进行中 / 已完成，由用户随时修改，持久保存。
- **系统状态**：即将到期 / 已延期，按时间实时推导，不落库。

设 now 为当前时间，deadline 为截止时间：

- 定时任务：deadline = 结束时间；无结束时间时取开始时间。
- 全天任务：deadline = 当天 23:59。

**显示判定顺序（从上到下，命中即停止）：**

| 顺序 | 显示状态 | 判定条件 |
| --- | --- | --- |
| 1 | 已完成 | 手动状态 = 已完成（系统状态不生效） |
| 2 | 已延期 | 未完成，且 now > deadline |
| 3 | 即将到期 | 未完成，且 now ≤ deadline，且 deadline − now ≤ 临期阈值 |
| 4 | 进行中 | 未完成，且手动状态 = 进行中 |
| 5 | 未开始 | 未完成，且手动状态 = 未开始 |

补充规则：

- 系统状态命中时覆盖手动状态的显示，但手动状态值仍保留在数据中，条件解除后自动恢复显示。
- 例：一个手动为“进行中”的任务进入临期区间后显示为“即将到期”；用户改期后，重新显示“进行中”。
- “已完成”优先级最高，已完成任务不会被判定为临期或逾期。
- 临期阈值默认 72 小时，可配置范围建议 1 小时–30 天。
- 未完成的“进行中”任务不因时间自动推进，也不自动变回“未开始”。
- 全天任务在当天计入截止，当天结束后未完成即变为已延期。
- 状态在界面刷新时实时重算，不依赖定时任务写入数据库。

### 5.2 待办摘要统计口径

- **今日待办**：截止日期为今天且未完成的任务。
- **临期**：显示状态为即将到期、且截止日期不是今天的未完成任务。
- **已延期**：显示状态为已延期（截止时间已过且未完成）。
- 三个数字互不重叠，点击后进入任务页对应筛选。
- 任务页“即将到期”筛选与状态定义一致，可包含今天到期的任务。
- 临期区的条目集合 = 即将到期集合 + 已延期集合，与摘要中的“临期”“已延期”两个数字一一对应。

### 5.3 优先级与排序

- 优先级分为高、中、低三级，默认中；取值为固定枚举，不支持自定义。
- 排序：优先级从高到低；同优先级按截止时间升序；再按创建时间升序。
- 优先级与状态的视觉表达见 3 UI 设计。

### 5.4 类别

- 类别为可选自由文本，一条任务最多一个类别。
- 保存时去除首尾空格；长度限制 1–20 个字符；空值视为未分类。
- 输入时提供已有类别建议，也允许直接输入新值。
- 类别不做独立管理实体，由任务中的现有值聚合而成。
- 任务页支持按类别分区与筛选；本期不提供类别批量重命名或合并。
- 筛选时忽略首尾空格与大小写差异，显示时保留用户输入的原文。

### 5.5 农历与节假日

- 农历与节气按内置算法计算，无需联网。
- 法定节假日使用年度数据表，包含放假区间、调休上班日、节日名称。
- 数据覆盖不足时显式提示，不允许静默显示错误信息。
- 数据更新方式待确认：随版本更新 / 在线拉取 / 手动导入。

### 5.6 临期提示规则

- 系统状态由界面按当前时间实时计算，无需定时触发、不写库、不产生通知。
- 任务在用户查看界面时若已处于临期或逾期区间，直接以对应状态与临期区展示；不存在“错过提醒”的补发问题。
- 已完成任务不进入临期区，也不计入临期与逾期统计。
- 修改日期或时间后，状态立即按新值重算，原有系统状态不保留。
- 程序未运行期间不发生任何提示；下次启动时按当前时间重新计算并展示。

## 6. 非功能需求

### 6.1 性能

- NFR-6.1.1 常驻空闲时 CPU 占用尽量接近 0，不得明显影响前台应用。
- NFR-6.1.2 以“轻量常驻”为内存目标，具体上限在技术选型阶段确定。
- NFR-6.1.3 冷启动到挂件可见 ≤ 3 秒（目标值）。
- NFR-6.1.4 页面切换、任务保存、筛选响应无明显卡顿（目标 ≤ 100ms）。
- NFR-6.1.5 在 5000 条任务规模下，日历与任务页仍可流畅操作。

### 6.2 稳定性与数据安全

- NFR-6.2.1 异常退出后重启应恢复数据，不出现半写损坏。
- NFR-6.2.2 数据写入采用事务或原子方式，关键操作失败需提示。
- NFR-6.2.3 崩溃后的自动重启或恢复提示：待确认。
- NFR-6.2.4 数据文件损坏或版本不兼容时，必须给出可读说明并保留原文件，不得静默覆盖或清空。

### 6.3 兼容性

- NFR-6.3.1 支持 Windows 10 与 Windows 11，最低版本待确认。
- NFR-6.3.2 支持 100%–200% DPI 缩放，以及多显示器混合缩放。
- NFR-6.3.3 与常见桌面整理、壁纸、桌面挂件软件共存；检测到同层软件时给出说明（待确认）。
- NFR-6.3.4 不要求管理员权限即可运行；只有用户显式选择“以管理员身份运行”时才触发 UAC。
- NFR-6.3.5 不修改系统设置、不篡改其他软件的启动项或文件关联。

### 6.4 隐私

- NFR-6.4.1 默认不联网、不埋点、不上传任何数据。
- NFR-6.4.2 启动项路径、文件路径等信息仅保存在本地。
- NFR-6.4.3 若提供在线更新或节假日拉取，须明示用途并允许关闭。
- NFR-6.4.4 锁定密码不得明文保存，必须使用加盐哈希存储；重置数据是唯一找回途径，需在界面明确告知。
- NFR-6.4.5 锁定状态下的遮蔽必须使内容不可辨认：仅强模糊不足以防止辨认时，必须叠加不透明遮罩。
- NFR-6.4.6 锁定状态不得通过托盘菜单、全局快捷键、进程重启等方式绕过。
- NFR-6.4.7 数据文件为明文，锁定只遮蔽界面；界面文案不得承诺“加密保护”“数据加密”，应表述为“锁定后界面上不可查看，数据文件本身可被直接读取”。

## 7. 风险与约束

| 编号 | 风险 / 约束 | 说明与应对方向 |
| --- | --- | --- |
| R-1 | 桌面层与系统毛玻璃不兼容 | 壁纸层挂件无法直接使用系统亚克力/云母，毛玻璃需基于壁纸自绘模糊；需求已定义为“背景模糊”而非系统材质 |
| R-2 | 被普通窗口完全覆盖 | 桌面模式下浏览其他应用时不可见，依赖 Win+D 或快捷键；这是形态本身的取舍 |
| R-3 | 与桌面整理软件冲突 | 腾讯桌面整理等也占用桌面层并可能接管图标，共存行为需实测并说明 |
| R-4 | 动态壁纸与壁纸切换 | 自绘模糊需跟随壁纸变化；动态壁纸下刷新成本较高，可降级为纯色/半透明背景 |
| R-5 | 节假日数据年度更新 | 法定节假日每年公布，需确定更新通道，否则次年数据缺失 |
| R-6 | 状态覆盖带来的认知成本 | 系统状态覆盖手动状态时，用户可能误以为手动设置失效；UI 需在状态旁说明“因到期自动变更”，并在改期后恢复 |
| R-7 | 多显示器 / DPI / 全屏判定差异 | 不同显卡驱动与全屏模式下行为不同，需要充分测试 |
| R-8 | 焦点管理 | 桌面层窗口的激活与取消激活需精细处理，避免“点不到”或“抢焦点” |
| R-9 | 区域级鼠标穿透 | 系统级“仅某区域穿透”能力有限，通常需要按鼠标位置动态切换窗口穿透标志；切换瞬间可能出现闪烁或点击判定偏差，需专项验证 |
| R-10 | 钉住与穿透下的交互歧义 | 控制栏可点意味着钉住不是全窗不可交互；UI 上必须清晰表达“只有顶部可点”，否则用户会误以为整块失效 |
| R-11 | 明文数据的安全边界 | 数据文件可直接打开阅读，也不防篡改；锁定只遮蔽界面，不具备数据保护能力，界面上不作过度安全承诺 |
| R-12 | 数据文件夹可被整体替换 | 替换数据文件夹即可替换全部内容，包括密码哈希；这是可移植性的代价，属预期行为 |
| R-13 | 快捷方式失效 | 目标文件被移动或删除后 `.lnk` 失效；需在界面明确标记并提供重新定位，避免用户误以为程序故障 |
| R-14 | 无备份与回收站 | 删除、清空、文件损坏均不可恢复；界面需在删除与清空时明确提示，避免误操作 |
